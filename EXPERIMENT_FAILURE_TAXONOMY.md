# AX Experiment v1 frozen failure taxonomy

This document consolidates the existing deterministic outcome and failure labels without changing their definitions.

## Agent outcome states

The deterministic scorer in `scripts/ceiling_scoring.py` defines:

- `CORRECT_SUPPORTED`
- `INCORRECT_SUPPORTED`
- `CORRECT_ABSTENTION`
- `UNJUSTIFIED_ABSTENTION`
- `HALLUCINATION`

System failures remain separate from readiness and answer quality. Existing system-failure examples are API error, timeout, `AGENT_BUDGET_EXCEEDED`, and parser crash.

## Primary defect attribution

The frozen primary-blocker flow in `AX_PROJECT_PLAN_v3.md` defines:

- `missing_data`
- `retrieval_failure`
- `version_ambiguity`
- `schema_mismatch`
- `privacy_block`
- `unreadable_source`
- `agent_failure`

Each task has one primary blocker for the MVP; failure classification is code-owned rather than generated by an LLM.

## F6_OUTPUT_CONTRACT

Leading or trailing prose, Markdown fences, duplicate fields, extra material, or any response that is not exactly one schema-valid raw JSON object sets `output_contract_valid = 0`. The primary failure may be `F6_OUTPUT_CONTRACT`.

Analysis-only semantic JSON extraction remains a separate metric. One unambiguous schema-valid JSON object may be extracted from an otherwise contract-invalid response, but the raw response is preserved unchanged, malformed JSON is never repaired, and semantic extraction never upgrades strict contract validity.
