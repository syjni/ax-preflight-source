# Phase 6 v4 주문 원장 검색 경로 감사

이 문서는 frozen v4의 두 주문 업무에서 답변과 보류가 섞인 원인을 확인한 읽기 전용 후속 감사다. 원본 v4 run과 source snapshot은 수정하거나 재실행하지 않았다.

## 확인 결과

- 원본 파일은 `04_주문/주문_원장_2026.xlsx`이며 file ID는 `FILE_950a2b2ed909ef4c`다.
- scanner는 이 파일을 `PARSED`로 기록했고 11,020자의 표 텍스트와 180개 행을 추출했다.
- 구조화 테이블 `TABLE_FILE_950a2b2ed909ef4c_Orders`가 존재하며, 답변한 실행은 이 테이블에서 최근 주문일 `2026-09-21`과 9월 주문금액 합계 `4,980,700원`을 조회했다.
- `DocumentIndex`에도 파일이 포함된다. 따라서 “표 파일이 인덱스에서 누락됐다”는 설명은 사실이 아니다.
- 정책 문서의 기준명 `주문원장_2026`과 실제 파일명 `주문_원장_2026.xlsx`는 검색 tokenizer가 공백·밑줄을 제거하므로 같은 검색 형태로 정규화된다. 파일명 불일치도 원인이 아니다.

## 재현된 검색 한계

현재 검색은 파일명과 전체 본문을 한 문서로 합친 char 2·3-gram BM25다. `주문원장_2026`을 정확히 검색해도 원장은 4위에 머물렀고, `가장 최근 주문`과 `이번 달 주문금액` 같은 업무 문장 검색에서는 상위 10개 밖으로 밀렸다. 실행별로 모델이 선택한 검색어와 `top_k`가 달라지면서 원장을 발견한 실행만 `query_table`에 도달했다.

frozen After 관측도 이 설명과 일치한다.

| 업무 | 답변 실행 | 보류 실행 | 확인된 차이 |
|---|---:|---:|---|
| 가장 최근 주문 | 1 | 2 | 답변 실행만 주문 원장 검색 hit와 Orders 조회에 도달 |
| 이번 달 주문금액 | 2 | 1 | 답변 실행만 Orders 합계 조회에 도달 |

따라서 두 `MIXED_OUTCOMES` Finding은 자료 공백이나 데이터 명칭 불일치가 아니라 `RETRIEVAL_LIMITATION`으로 표시한다. 이는 “에이전트만 흔들렸다”는 추정도 아니다. 동일 인덱스에서 query wording과 top-k에 따라 기준 원장의 노출 여부가 달라지는 제품 탐색 경로의 재현 가능한 한계다.

## 조치 범위

제출 전에는 frozen v4를 고쳐 쓰지 않는다. 화면과 문서에 알려진 한계로 공개하고, 두 Finding의 권고를 다음 방향으로 통일한다.

1. 정책이 지정한 기준 원장을 table ID 또는 관리되는 별칭으로 직접 연결한다.
2. 파일명 exact-match boost 또는 표 제목 전용 검색 필드를 둔다.
3. 상위-k 밖의 기준 자료가 있을 때 query 확장이나 구조화 자료 목록 조회를 제공한다.
4. 수정 후 같은 질문·설정으로 3회 이상 다시 실행해 혼재가 사라지는지 확인한다.

이 조치는 반품 FAQ 수정의 효과와 별개다. 전체 Before/After 개선의 인과 주장에도 사용하지 않는다.
