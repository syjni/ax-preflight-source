# Phase 6 v4 비교 v1 후속 감사

이 문서는 frozen v4를 다시 실행하거나 고쳐 쓰지 않고, 최초 비교 규칙 v1의 Before 4/10·After 2/10이 무엇을 셌는지 원자료 수준에서 분해한 역사적 후속 감사다. 이후 이 검토에서 확인된 정규화 민감도와 혼재 분류 문제를 일반 규칙으로 해결한 [의미 비교 v2](PHASE6_V4_COMPARISON_V2.md)가 현재 제품 해석이다. v2 결과는 Before 5/10 안정·3/10 일관 보류·2/10 혼재, After 6/10 안정·2/10 일관 보류·2/10 혼재다.

## 확인된 사실

- 두 source tree는 각각 30개 파일이며 바뀐 파일은 `06_고객지원/FAQ_2026.txt` 한 개뿐이다.
- v1에서 Before는 안정이었지만 After에서 안정 판정을 잃은 것으로 보인 업무는 정확히 3개다.
- 세 업무가 인용한 파일에는 바뀐 FAQ가 없다. 인용한 업무 파일은 Before/After에서 바이트가 같다.
- 따라서 v1이 표시한 세 건을 문서 수정의 결과나 문서 결함으로 귀속할 근거는 없다. 그중 두 건은 v2에서 의미적으로 같은 답으로 재분류되고, 한 건은 답변·보류 혼재로 분리된다.

기계 재현 결과는 [`artifacts/posthoc_phase6_v4_stability/ANALYSIS.json`](../artifacts/posthoc_phase6_v4_stability/ANALYSIS.json)에 보존한다. `DATA_CAUSE_NOT_ESTABLISHED`는 “모델만 원인”이라는 뜻도 아니다. 이 snapshot만으로 데이터 원인을 입증하지 못했다는 제한된 판정이다.

## 제품과 발표에 반영한 해석

1. 빈 결과·식별자 집합·수치와 단위·영업일 표현을 의미 비교하는 v2를 현재 화면에 사용한다.
2. 답변과 보류가 섞인 업무는 `MIXED_OUTCOMES`로 분리하고 문서 결함이 아닌 **사람 검토가 필요한 실행 결과 혼재**로 표시한다.
3. v1의 4/10·2/10은 감사값으로 보존하되 현재 품질 헤드라인에는 사용하지 않는다.
4. 발표의 전후 효과 주장은 실제 변경 파일과 직접 연결되는 반품 업무의 0/3→3/3 전환으로만 제한한다. v2의 전체 5/10→6/10은 같은 run의 기술적 재분류를 포함하므로 인과 개선으로 주장하지 않는다.

두 주문 업무의 혼재 원인은 이후 [주문 원장 검색 경로 감사](PHASE6_V4_ORDER_RETRIEVAL_REVIEW.md)에서 추가 확인했다. 정책 기준명과 실제 파일명은 검색 정규화상 동일했고, 원장도 인덱스에 있었다. 문제는 정확한 기준명 검색에서도 원장이 4위로 밀리고 업무 문장 검색에서는 상위 10개 밖으로 밀릴 수 있는 현재 BM25·top-k 탐색 경로다.
