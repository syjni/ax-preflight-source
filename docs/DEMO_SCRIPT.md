# AX Preflight 3분 시연 대본

사용자의 폴더를 로컬에서 직접 점검할 수 있음을 먼저 보여 주고, 30개 회사 파일의
10개 업무를 Before/After에서 각 3회 실행한 검증 결과로 핵심 가치를 설명한다. 라이브
Kiro 실행은 발표의 필수 경로가 아니다.

시연 기준은
[`v0.5.0-submission`](https://github.com/syjni/ax-preflight-source/releases/tag/v0.5.0-submission)이다.
공개 데모와 로컬 검토 모드는 읽기·정적 점검 경로이고, live mode만 Kiro CLI를 사용한다.
Amazon Bedrock 직접 연동은 이 저장소에 없다.

## 시작 전

Windows에서는 저장소 루트에서 다음 파일을 실행한다.

```bat
start-local.cmd
```

macOS / Linux에서는 API를 로컬 검토 factory로 시작한다.

```bash
AX_PRODUCT_FROZEN_RESULTS_ROOT=artifacts/phase6_product_demo_v4/runs \
  python -m uvicorn ax_product.api:create_local_review_app_from_env \
  --factory --host 127.0.0.1 --port 8000
```

두 번째 터미널에서 `cd results_console && npm run dev -- --port 5173`을 실행하고 `http://127.0.0.1:5173/`을 연다.

## 0:00–0:20 — 직접 실행 가능성

“공개 주소에서는 검증된 예시를 바로 볼 수 있고, 내려받은 소스에서는 여러분의 문서
폴더를 외부 서비스에 보내지 않고 localhost의 관리 사본으로 점검할 수 있습니다.”

첫 관리자 설정·프로젝트 화면을 거쳐 **내 자료 점검**의 브라우저 파일·폴더 선택과 준비도·보완 항목,
실제 업무 등록·승인을 짧게 보여 준다. 별도로 확인할
폴더가 없다면 이 단계는 설명만 하고 검증된 대표 흐름으로 이동한다.

## 0:20–0:35 — 검증된 동결 PoC

첫 화면에서 **검증된 예시 보기**를 눌러 `읽기 전용 · 실시간 실행 아님` 표시와 승인 업무,
실행 3회, 직접 근거 3/3, 실패 복구, 모델·데이터 경계, 비용, 감사·보존, 최종 보고서가
한 흐름으로 연결됐음을 보여 준다. 조직별 승인이 없는 항목은 감추지 않아 최종 추천이
`CONDITIONAL`임을 말한다.

## 0:35–0:50 — 문제

“문서가 있어도 기준이 충돌하면 AI 업무는 실패합니다. 문제는 도입 전에 어떤 업무가 왜 막힐지 알기 어렵다는 것입니다.”

## 0:50–1:05 — 해법

“AX Preflight는 실제 업무를 반복 실행하고, 구조화 제출과 같은 실행의 근거만으로 막히거나 흔들린 업무와 다음 검토 지점을 보여 줍니다.”

## 1:05–1:40 — Before

“한빛유통 30개 파일의 정적 Readiness는 100점입니다. 하지만 반품 업무는 세 번 모두 답하지 못했습니다.”

조작:

1. 결과 콘솔 상단 **검증된 대표 흐름**에서 **보류 근거 보기**를 누른다.
2. `5 / 10 반복 안정`, `3 / 10 일관된 보류`, `2 / 10 불안정·검토 필요`, 관측 실행 30회를 가리킨다.
3. 반품 충돌 Finding의 **정리 전 실행에서 인용한 서로 충돌한 원문**을 펼쳐 확인한다.
4. 서로 버전 관계로 보이지 않는 `FAQ_2026.txt`의 14일과 `반품_교환_정책_2026.docx`의 30일, 그리고 **권고 조치**를 가리킨다.

“FAQ는 14일, 공식 정책은 30일입니다. AX Preflight는 충돌한 두 문서와 다음 조치를 지목합니다.”

## 1:40–2:20 — After

“FAQ의 14일 문장을 제거한 뒤 반품 업무는 세 번 모두 30일로 답했고, 인용 응답에서도 그 값이 확인됐습니다. 기존 충돌은 ‘After에서 재현되지 않음’이 됐습니다.”

조작:

1. 결과 콘솔 상단 **검증된 대표 흐름**에서 **30일 근거 확인**을 누른다.
2. `6 / 10 반복 안정`, `2 / 10 일관된 보류`, `2 / 10 불안정·검토 필요`를 가리킨다.
3. 이전 반품 충돌의 **After에서 재현되지 않음** 표시를 가리킨다.
4. 자동으로 열린 대표 run에서 `30일`과 `근거 직접 일치(DIRECT_MATCH)`를 보여 준다.
5. 같은 섹션의 **검색·근거 경로**에서 정책 문서가 검색 1순위이고 최종 인용 자료로 연결된 경로를 보여 준다.

“같은 동결 실행을 의미 기준으로 비교하면 Before 5, After 6개 업무가 반복 안정이고, 각각 2개는 답변과 보류가 섞였습니다. 전체 차이는 인과 효과로 주장하지 않고, 직접 수정한 반품 업무의 0/3에서 3/3 전환만 개선으로 설명합니다.”

## 2:20–2:45 — 차별점

“자연어 답변이 아니라 `submit_answer`의 구조화 결과만 저장합니다. 인용 응답과 값이 맞는지도 별도로 검사하되, 이것을 정답률이라고 부르지 않습니다.”

시간이 허용되면 **관리자 1페이지**의 수정 대상·권고 조치·Before/After를 보여 주고 **PDF로 저장 / 인쇄** 버튼을 가리킨다.

## 2:45–3:00 — Kiro 활용과 결론

“라이브 모드에서는 Kiro CLI가 실행을 오케스트레이션하고, 기본 구성의 Claude Sonnet 모델이 AX product MCP의 네 데이터 도구와 구조화 제출 도구를 사용합니다. AX Preflight는 AI 도입 전에 이 업무를 반복해도 되는지, 데이터와 실행 중 어디를 먼저 검토할지 보여 주는 진단 계층입니다.”

After 화면을 유지한 채 마친다. 통제 데모 승인과 프로젝트 OWNER가 만든 실제 PoC 승인 구분을 분명히 한다. 반복 실행 P0는 opt-in 라이브 API에서 진행률·부분 실패·안전한 제어와 재시작 복구를 제공하지만, 발표용 읽기 전용 배포에서는 변경 동작이 꺼져 있다. SSO·MFA·조직 tenant 격리·다중 worker lease·비용 quota 같은 운영 제한은 README의 범위대로 답한다.

## 복구 체크리스트

- API 시작 실패: frozen 경로가 `artifacts/phase6_product_demo_v4/runs`인지 확인한다.
- API 503: read-only 모드의 실행 요청 거부는 정상이다. dataset·run 조회만 사용한다.
- 전체 수치 설명이 길어지면 반품 충돌 Finding과 After의 3/3 `30일` 결과만 보여 준다.
- 라이브 Kiro는 발표 중 실행하지 않고 frozen snapshot을 유지한다.
- frozen snapshot은 수정하거나 재생성하지 않는다.

## 예상 질문 한 문장 답변

- **왜 기존 4/10·2/10과 지금 5/10·6/10이 다른가요?** “기존 v1은 같은 의미의 표현·단위 차이와 한 번의 보류를 과도하게 셌습니다. 사후 개별 답에 맞추지 않고 빈 집합·식별자 집합·수치와 단위·영업일을 다루는 일반 규칙 v2로 재분류했으며, v1도 감사 정보로 남겼습니다.”
- **DIRECT_MATCH면 정답인가요?** “아닙니다. 인용한 같은-run 구조화 응답과 답 값이 일치했다는 좁은 판정이며, 업무 의미 전체의 정답률은 아닙니다.”
- **불일치면 문서를 고쳐야 하나요?** “아닙니다. 먼저 고정 설정 재실행과 조회 경로를 비교하고, 특정 자료의 모호성이 재현될 때만 문서를 수정합니다.”
- **주문 원장이 있는데 왜 일부 실행은 못 찾았나요?** “원장과 Orders 테이블은 정상 파싱·인덱싱됐지만, 현재 BM25에서는 정확한 기준명 검색도 4위로 밀릴 수 있습니다. 실행별 검색어와 top-k에 따라 도달 여부가 갈린 제품 한계로 확인했고, 자료 공백으로 포장하지 않고 공개했습니다.”
- **AWS와 Kiro, Claude는 어디에 쓰였나요?** “Kiro CLI가 실행별 agent를 오케스트레이션하고 요청 모델 기본값 `claude-sonnet-5`가 AX product MCP 도구를 사용합니다. scanner·실행 계약·MCP·Finding/Evidence·API·화면은 AX Preflight 코드이고, 이 저장소에 없는 Bedrock 직접 연동은 주장하지 않습니다.”
- **회사 데이터가 외부로 나가지 않나요?** “원본과 산출물은 로컬 경로에서 관리하지만, 라이브 실행에서는 도구가 반환한 문서 일부나 구조화 값이 설정된 모델 처리 경계로 전달될 수 있습니다. 공급자 계정의 보존·학습·리전 정책은 별도로 확인해야 합니다.”
