# AX Preflight 심사자 빠른 시작

AX Preflight는 두 경로를 한 화면에서 제공합니다.

- **내 자료 점검:** 파일·폴더를 브라우저에서 선택해 준비도와 파일별 보완 항목을 표시합니다.
- **검증된 예시:** 30개 회사 파일에서 발견한 반품 정책 충돌과 수정 후 0/3 → 3/3 변화를 재현합니다.

## 1. Windows에서 시작 — 권장 Docker 방식

필요 환경은 실행 중인 Docker Desktop입니다. GitHub의 **Code → Download ZIP**으로
소스를 받은 뒤 `C:\ax-preflight`처럼 짧은 경로에 풉니다. 프로젝트 루트의
`start-docker.cmd`를 더블클릭하거나 명령 프롬프트에서 실행합니다.

```bat
cd /d C:\ax-preflight
start-docker.cmd
```

처음 한 번은 컨테이너 이미지를 만들기 때문에 네트워크 연결과 몇 분의 시간이 필요할
수 있습니다. 브라우저는 `http://127.0.0.1:8000/`에서 자동으로 열립니다. 이 실행에는
PDF 표 추출과 Tesseract 한국어·영어 OCR이 포함됩니다.

Docker를 사용할 수 없다면 Python 3.12+와 Node.js 20+를 설치하고 `start-local.cmd`를
실행합니다. 이 경우 브라우저는 `http://127.0.0.1:5173/`에서 열리며, OCR은 Tesseract와
`kor`, `eng` 언어팩이 설치된 경우에만 활성화됩니다.

## 2. 내 파일로 확인

1. **결과 콘솔** 맨 위의 **내 자료 점검**으로 이동합니다.
2. **파일 선택** 또는 **폴더 선택**을 누릅니다. 점선 영역으로 끌어 놓아도 됩니다.
3. **내 자료 점검 시작**을 누릅니다.
4. 준비도 점수, 파싱된 파일·PDF 표·OCR 처리 수와 **먼저 보완할 항목**을 확인합니다.
5. 각 항목을 펼쳐 해당 파일과 권고 조치를 확인하고, **전체 준비도 보기**에서 세부 점수를 확인합니다.

선택한 파일은 같은 컴퓨터의 `localhost`로만 전송되고 AX Preflight의 로컬 관리 폴더에
복사됩니다. 외부 서비스와 모델은 호출하지 않습니다. 화면의 **이 점검 기록 제거**는
마스킹된 보고서와 관리 사본을 지우며 원본은 그대로 둡니다. 파일 복사를 원하지 않으면
**폴더 경로 입력** 탭을 선택하십시오. 로컬 API가 그 경로를 직접 읽습니다.

## 3. 제품 가치 확인

같은 화면의 **검증된 대표 흐름**에서 다음 두 버튼을 차례로 엽니다.

1. **보류 근거 보기:** Readiness 100점이면서 반품 업무가 3회 모두 보류된 이유와 14일·30일 충돌 원문을 확인합니다.
2. **30일 근거 확인:** 충돌 문장을 정리한 뒤 3회 모두 답변했고 인용 근거와 값이 직접 일치하는지 확인합니다.

이어 **검색·근거 경로**에서 검색 후보 → 읽은 자료 → 최종 인용의 연결을 보고,
**관리자 1페이지**에서 Before/After 요약을 인쇄 또는 PDF로 저장할 수 있습니다.

## 4. 종료와 문제 해결

Docker 방식은 `stop-docker.cmd`로 종료합니다. 직접 실행 방식은 두 명령 창에서 각각
`Ctrl+C`를 누릅니다.

- 포트 8000 또는 5173이 사용 중이면 이전 AX Preflight 창을 닫고 다시 실행합니다.
- Docker Desktop이 실행되지 않았다는 메시지가 나오면 Docker Desktop을 먼저 시작합니다.
- 경로 입력에서 폴더를 찾지 못하면 탐색기 주소 표시줄의 전체 경로를 복사합니다.
- OCR 설치 필요가 표시되면 Docker 방식을 사용하거나 Tesseract `kor`, `eng` 언어팩을 설치합니다.
- 읽기 오류가 있으면 해당 파일 권한과 손상 여부를 확인합니다.
- 공개 데모는 정적 페이지이므로 내 파일 입력이 비활성화됩니다. 반드시 내려받은 소스의 로컬 검토 모드를 사용하십시오.
