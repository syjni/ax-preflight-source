# AX Preflight 심사자 빠른 시작

AX Preflight는 두 경로를 한 화면에서 제공합니다.

- **내 자료 점검:** 파일·폴더를 브라우저에서 선택해 준비도와 파일별 보완 항목을 표시합니다.
- **검증된 예시:** 30개 회사 파일에서 발견한 반품 정책 충돌과 수정 후 0/3 → 3/3 변화를 재현합니다.

## 1. Windows에서 시작 — 권장 Docker 방식

필요 환경은 실행 중인 Docker Desktop입니다. GitHub의 **Code → Download ZIP**으로
소스를 받은 뒤 `C:\ax-preflight`처럼 짧은 경로에 풉니다. 프로젝트 루트의
`start-docker.cmd`를 더블클릭하거나 명령 프롬프트에서 실행합니다.

```bat
cd /d C:\ax-preflight
start-docker.cmd
```

처음 한 번은 컨테이너 이미지를 만들기 때문에 네트워크 연결과 몇 분의 시간이 필요할
수 있습니다. 브라우저는 `http://127.0.0.1:8000/`에서 자동으로 열립니다. 이 실행에는
PDF 표 추출과 Tesseract 한국어·영어 OCR이 포함됩니다.

Docker를 사용할 수 없다면 Python 3.12+와 Node.js 20+를 설치하고 `start-local.cmd`를
실행합니다. 이 경우 브라우저는 `http://127.0.0.1:5173/`에서 열리며, OCR은 Tesseract와
`kor`, `eng` 언어팩이 설치된 경우에만 활성화됩니다.

## 2. 내 파일로 확인

1. 첫 화면에서 관리자 계정과 기본 프로젝트를 만듭니다. 비밀번호는 12자 이상이며 아이디를 포함할 수 없습니다.
2. 로그인 후 **결과 콘솔** 맨 위의 현재 프로젝트를 확인합니다.
3. **파일 선택** 또는 **폴더 선택**을 누릅니다. 점선 영역으로 끌어 놓아도 됩니다.
4. **내 자료 점검 시작**을 누릅니다.
5. 준비도 점수, 파싱된 파일·PDF 표·OCR 처리 수와 **먼저 보완할 항목**을 확인합니다.
6. **업무 등록·승인**에 실제 질문과 성공 기준을 적고 OWNER 계정으로 승인합니다.
7. **모델 연결·데이터 경계·비용**에서 현재 실행 가능 여부와 필요한 조치를 확인합니다.
8. 각 항목을 펼쳐 해당 파일과 권고 조치를 확인하고, **전체 준비도 보기**에서 세부 점수를 확인합니다.

선택한 파일은 같은 컴퓨터의 `localhost`로만 전송되고 AX Preflight의 로컬 관리 폴더에
복사됩니다. 외부 서비스와 모델은 호출하지 않습니다. 화면의 **이 점검 기록 제거**는
마스킹된 보고서와 관리 사본을 지우며 원본은 그대로 둡니다. 파일 복사를 원하지 않으면
**폴더 경로 입력** 탭을 선택하십시오. 로컬 API가 그 경로를 직접 읽습니다.

화면의 **구성원과 권한**에서 관리자는 로그인 계정을 만들고, 프로젝트 OWNER는
`EDITOR`(자료·업무 등록) 또는 `VIEWER`(조회) 권한을 줄 수 있습니다. 다른 프로젝트의
로컬 자료와 업무는 목록과 직접 URL 모두에서 숨겨집니다. 관리자는 다른 사용자의
로그인 세션을 종료할 수 있고, OWNER는 OWNER가 아닌 구성원의 프로젝트 권한을
회수할 수 있습니다.

같은 패널의 **감사·보존·완전 삭제**를 열면 전체 관리 inventory, 해시 연결 감사 이벤트,
보존 검토 주기와 법적 보존을 확인할 수 있습니다. OWNER가 정확한 프로젝트 이름을
입력하면 관리 데이터를 삭제하고, 서버가 모든 관리 저장소와 감사 로그에서 프로젝트
식별자가 사라졌는지 확인한 삭제 증명서를 반환합니다. 원본 파일과 동결 예시는 유지하며,
실행 중 작업·법적 보존·감사 무결성 오류가 있으면 삭제가 차단됩니다.

## 3. 내 자료로 AI 업무 실행 — Kiro 설정 환경

기본 Docker·로컬 검토 모드는 파일을 정적으로 점검하므로 외부 모델을 호출하지
않습니다. Kiro CLI와 사용할 모델 자격 증명이 이미 설정된 컴퓨터에서는 README의
**내 자료로 실제 AI 업무 실행** 명령으로 라이브 factory를 시작한 뒤 다음 순서로
진행합니다.

1. OWNER가 **모델 연결·데이터 경계·비용**에서 모델, 최근 24시간 실행 수·예상 비용,
   배치·동시 실행 한도를 저장합니다.
2. 자료 등급을 선택하고 도구 출력의 모델 전달, 공급자 정책, 민감정보 검토를 모두
   확인해 해당 자료와 모델 조합을 승인합니다.
3. **조회와 실행**에서 질문을 실행하거나 **반복 실행 오케스트레이션**에서 승인 업무를
   반복합니다.
4. 실행 뒤 같은 패널의 예약 실행 수와 예상 비용이 증가했는지 확인합니다.

자격 증명 원문은 화면이나 프로젝트 상태 파일에 저장·표시하지 않습니다. 비용은 실제
청구액이 아니라 OWNER가 설정한 실행당 추정치이며, 서버는 실행 예약 전에 잔여 한도를
다시 검사합니다. 모델 변경·승인 만료·한도 소진 시 새 실행이 차단됩니다.

## 4. 제품 가치 확인

같은 화면의 **검증된 대표 흐름**에서 다음 두 버튼을 차례로 엽니다.

1. **보류 근거 보기:** Readiness 100점이면서 반품 업무가 3회 모두 보류된 이유와 14일·30일 충돌 원문을 확인합니다.
2. **30일 근거 확인:** 충돌 문장을 정리한 뒤 3회 모두 답변했고 인용 근거와 값이 직접 일치하는지 확인합니다.

이어 **검색·근거 경로**에서 검색 후보 → 읽은 자료 → 최종 인용의 연결을 보고,
**관리자 1페이지**에서 Before/After 요약을 인쇄 또는 PDF로 저장할 수 있습니다.
실제 로컬 자료에서는 **PoC 평가·승인**이 준비도, 승인 업무, 실행 표본, 직접 근거,
열린 신호와 운영 통제를 PASS/WARN/BLOCK으로 집계합니다. OWNER 판단에는 범위·위험
확인과 메모가 필요하며, 지표가 바뀌거나 유효 기간이 끝나면 다시 검토해야 합니다.

## 5. 종료와 문제 해결

Docker 방식은 `stop-docker.cmd`로 종료합니다. 직접 실행 방식은 두 명령 창에서 각각
`Ctrl+C`를 누릅니다.

- 포트 8000 또는 5173이 사용 중이면 이전 AX Preflight 창을 닫고 다시 실행합니다.
- Docker Desktop이 실행되지 않았다는 메시지가 나오면 Docker Desktop을 먼저 시작합니다.
- 경로 입력에서 폴더를 찾지 못하면 탐색기 주소 표시줄의 전체 경로를 복사합니다.
- OCR 설치 필요가 표시되면 Docker 방식을 사용하거나 Tesseract `kor`, `eng` 언어팩을 설치합니다.
- 읽기 오류가 있으면 해당 파일 권한과 손상 여부를 확인합니다.
- 공개 데모는 정적 페이지이므로 내 파일 입력이 비활성화됩니다. 반드시 내려받은 소스의 로컬 검토 모드를 사용하십시오.

[데이터 처리와 개인정보 경계](DATA_AND_PRIVACY.md)를 참고하십시오.
