# AX Preflight 심사자 빠른 시작

AX Preflight는 두 경로를 한 화면에서 제공합니다.

- **내 자료 점검:** 심사자의 로컬 문서 폴더를 읽어 준비도와 파일별 보완 항목을 표시합니다.
- **검증된 예시:** 30개 회사 파일에서 발견한 반품 정책 충돌과 수정 후 0/3 → 3/3 변화를 재현합니다.

## 1. Windows에서 시작

필요 환경은 Python 3.12 이상과 Node.js 20 이상입니다. GitHub의 **Code → Download
ZIP**으로 소스를 받은 뒤 `C:\ax-preflight`처럼 짧은 경로에 풉니다. 프로젝트 루트의
`start-local.cmd`를 더블클릭하거나 명령 프롬프트에서 실행합니다.

```bat
cd /d C:\ax-preflight
start-local.cmd
```

처음 한 번은 Python·Node 의존성을 설치하므로 네트워크 연결과 몇 분의 시간이 필요할
수 있습니다. API용 명령 창과 Results Console용 명령 창을 모두 열어 두십시오. 브라우저는
`http://127.0.0.1:5173/`에서 자동으로 열립니다.

## 2. 내 파일로 확인

1. **결과 콘솔** 맨 위의 **내 자료 점검**으로 이동합니다.
2. PDF·DOCX·XLSX·CSV·TXT가 들어 있는 폴더의 전체 경로를 붙여 넣습니다.
3. **내 자료 점검 시작**을 누릅니다.
4. 준비도 점수, 파싱된 파일 수와 **먼저 보완할 항목**을 확인합니다.
5. 각 항목을 펼쳐 해당 파일과 권고 조치를 확인하고, **전체 준비도 보기**에서 세부 점수를 확인합니다.

브라우저는 파일을 외부 서버에 업로드하지 않습니다. 같은 컴퓨터의 로컬 API가 입력
폴더를 직접 읽고 원본을 수정·복사하지 않습니다. 이 단계는 모델 호출 없이 동작합니다.
마스킹된 점검 보고서만 Git에서 제외된 `artifacts/local_datasets/`에 남으며, 화면의
**이 점검 기록 제거**로 삭제할 수 있습니다.

## 3. 제품 가치 확인

같은 화면의 **검증된 대표 흐름**에서 다음 두 버튼을 차례로 엽니다.

1. **보류 근거 보기:** Readiness 100점이면서 반품 업무가 3회 모두 보류된 이유와 14일·30일 충돌 원문을 확인합니다.
2. **30일 근거 확인:** 충돌 문장을 정리한 뒤 3회 모두 답변했고 인용 근거와 값이 직접 일치하는지 확인합니다.

이어 **검색·근거 경로**에서 검색 후보 → 읽은 자료 → 최종 인용의 연결을 보고,
**관리자 1페이지**에서 Before/After 요약을 인쇄 또는 PDF로 저장할 수 있습니다.

## 4. 종료와 문제 해결

검토를 마치면 두 명령 창에서 각각 `Ctrl+C`를 누릅니다.

- 포트 8000 또는 5173이 사용 중이면 이전 AX Preflight 창을 닫고 다시 실행합니다.
- 폴더를 찾지 못하면 탐색기 주소 표시줄에서 전체 경로를 복사해 입력합니다.
- 읽기 오류가 있으면 해당 파일 권한과 손상 여부를 확인합니다.
- 공개 데모는 정적 페이지이므로 내 파일 입력이 비활성화됩니다. 반드시 내려받은 소스의 로컬 검토 모드를 사용하십시오.

기술 명령과 전체 테스트는 [README](../README.md), 제출 구조는
[심사·제출 가이드](../SUBMISSION.md), 데이터 경계는
[데이터 처리와 개인정보 경계](DATA_AND_PRIVACY.md)를 참고하십시오.
