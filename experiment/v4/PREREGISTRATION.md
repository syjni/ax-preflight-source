# AX v4 사전등록 초안 — 출력 전달과 답 표현

작성일: 2026-09-22. 실험 ID: `ax-exp-v4`. 이 문서는 **공식 실행 전 사전등록 설계**다. 현재 동결·실행 가능 상태는 `experiment/frozen/ax-exp-v4-manifest.json`의 존재와 `scripts/v4_preflight.py` 결과로 판정한다. 새 회사 자료 4개와 16개 새 과제 후보를 `experiment/v4/CANDIDATE_MANIFEST.json`에 만들고 원문 정답·정적 도구 접근을 점검했다. 이 후보 과제에 대한 Kiro 실행은 없으며, 개발 검증은 별도 한울상점 자료로만 수행했다.

## 질문과 범위

v3에서 원문 엄격 JSON은 27/64, 정답과 엄격 JSON의 교집합은 처리군 Ceiling 9/24였다. 37개 형식 실패는 모두 JSON 앞 설명문을 포함했다. K02·O06·K03에서는 답 표현이 고정 판정에 영향을 주었다. v4는 **새로운 미공개 과제**에서 (1) 모델 원문의 형식 준수, (2) 결정론적 출력 게이트를 거친 전달 가능성, (3) 사전에 정의한 답·단위·항목 표현으로 채점한 내용 정확도를 분리해 측정한다. v3와의 직접적인 인과 비교를 주장하지 않는다.

변경 범위는 v4 출력 스키마, 과제별 답 유형 안내, 결정론적 출력 게이트, v4 채점 규칙이다. 증거 접근 결함의 Before/Ceiling 비교는 이번 v4 질문에 넣지 않는다. 이 선택으로 새 실험은 **출력·표현 계약의 실용 성능**을 측정하며, Scanner 접근성 효과를 다시 추정하지 않는다.

## 계획된 미공개 평가

- 새 회사 자료 묶음과 새 질문 16개를 별도 `experiment/v4/heldout/`에 준비한다. v3의 16개 질문·원문 답변은 개발 참고 자료로만 취급하고 v4 미공개 분모에 넣지 않는다. 새 과제 ID 및 질문 문구가 v3와 겹치지 않는지 자동 확인하고, 의미상 재사용 여부는 별도 사람 검토로 확인한다.
- 층화: 비율 4, 임계값 4, 항목 집합 4, 정확 문자열 또는 근거 부족 보류 4. 마지막 층에는 보류 정답 2개를 포함한다. 각 정답은 원문 자료에서 독립적으로 재산출하고, 근거 경로와 기대 답을 실행 전에 확정한다. 보류 문제는 자료 전체를 점검해 답 부재를 확인한다.
- 한 가지 증거 프로필에서 과제당 새로운 Kiro 세션 2회: 총 16 × 2 = **32회**. 반복은 같은 과제의 변동성을 측정하며 독립적인 32개 과제로 세지 않는다. 과제 순서는 동결된 매니페스트 순서, 1회차 전체 후 2회차 전체로 한다. 각 실행은 신선한 Kiro 프로세스와 단일 사용자 턴을 사용한다.
- 모델은 `claude-sonnet-5`, 도구는 기존 네 AX 읽기 도구, 실행 백엔드는 `AUTOMATED_FRESH_PROCESS_V2`로 등록한다. Kiro CLI 2.23.0의 v2 엔진을 별도 개발 자료로 비대화형 실행했고, 로컬 세션 JSON/JSONL에 정확한 Prompt 이벤트와 완료 응답이 남는 것을 확인했다. 각 공식 실행은 `shell=False`의 단일 프롬프트 인수, 새 프로세스·새 세션을 사용한다. CLI나 엔진이 바뀌면 개발 검증과 재동결을 먼저 한다.
- 모델 프롬프트는 `experiment/v4/AGENT_PROMPT.txt`를 기반으로 하되, 새 증거 프로필과 실행별 경로를 주입한 에이전트 설정을 해시로 고정한다. 과제 프롬프트는 `scripts/v4_prompt.py`가 `category`, `question`, `answer_kind`, 숫자 단위 이름만 투영한다. 기대 답, 허용 오차, 동의형, 근거 파일 목록, 보류 정답 여부는 모델에게 전달하지 않는다.

## 출력과 점수의 고정 규칙

`scripts/v4_contract.py`의 v4 스키마는 `final_answer`, `unit`, `explanation`, `source_ids`, `abstain` 다섯 필드를 모두 요구한다. 답 유형은 숫자, 짧은 항목 문자열 배열, 정확 문자열 중 하나다. 유효한 보류는 `final_answer=null`, `unit=null`, `abstain=true`다.

모델 **원문 형식 준수**는 응답 전체가 단일 스키마 유효 JSON 객체일 때만 성공이다. 전달 게이트는 원문을 보존하면서 유일한 스키마 유효 객체를 찾고, 중괄호를 포함한 다른 텍스트 또는 여러 유효 객체가 있으면 거부한다. 수용 시 이를 정렬된 키·고정 구분자로 다시 직렬화해 전달한다. 게이트가 설명문이나 코드 펜스를 제거해도 모델 원문 형식 성공으로 세지 않는다. 게이트 거부는 실행 무효가 아니라 아래 1차 지표의 실패다. 자동 재질문·재시도는 하지 않는다.

`scripts/v4_scoring.py`의 규칙:

- 비율·임계값은 숫자 `final_answer`와 사전에 등록된 `unit`을 요구한다. 각 단위의 정규화 배율과 정규화 단위 절대 허용오차를 과제 매니페스트에 고정한다. 비율에서 `ratio`와 `percent`를 모두 허용하려면 둘 모두를 사전등록한다. 예를 들어 소수 비율 4자리 또는 백분율 2자리 표시 허용 시 정규화 절대 허용오차는 최대 `0.00005`로 둔다. 임계값 과제는 초과 기준인지 최초 해당 일차인지 질문에 명시하고 정수 기대값·허용오차 0을 사용한다.
- 항목 집합은 `final_answer` 배열의 각 원소를 사전등록된 개념·허용형 목록과 **원소 전체 일치**로 비교한다. 필수 개념 전부가 한 번씩 있어야 하고 미등록·중복 항목은 실패다. 부정형은 긍정형의 별칭으로 넣지 않는다. 설명문의 내용으로 빠진 답을 보충하지 않는다.
- 정확 문자열은 등록된 허용형 전체 일치로 판정한다. 보류 정답은 `abstain`에 따라 별도로 판정한다.

**1차 지표:** 32개 유효 실행 중 고정 답 판정이 정답이고 전달 JSON도 유효한 실행 수. 게이트 거부 또는 추출 불가 응답은 1차 지표 실패로 센다. **보조 지표:** 모델 원문 엄격 JSON 준수율, 게이트 후 JSON 전달율, 고정 내용 정답률, 게이트 거부율, 층별 결과, 두 반복의 일치율. 결과는 실행 수와 과제 수를 함께 보고하며, v3의 64회와 단순 합산하거나 v3를 미공개 대조군으로 쓰지 않는다.

`scripts/v4_evaluation.py`는 한 원문 응답에 대해 위 지표의 실행별 판정과 원문·전달 JSON 해시를 함께 산출한다. 이 평가는 실행 유효성 감사가 끝난 뒤에만 공식 집계에 들어간다.

## 실행 유효성 및 동결 조건

v3에서 사용한 정확 프롬프트 바이트 비교, 단일 Prompt 이벤트, 실행별 새 세션·새 프로세스, 도구 및 증거 프로필 영수증, 소스·에이전트 설정 해시 검사를 v4에도 적용한다. 입력 프롬프트 또는 런타임 증거가 잘못된 시도는 INVALID로 보관하고 해당 슬롯을 재시도한다. 모델이 틀린 답이나 형식 위반을 낸 시도는 VALID 실행으로 남긴다. 공식 평가 중 코드·자료·문제·정답·허용형·허용오차를 수정하지 않는다.

공식 시작 전 다음이 모두 필요하다: 후보 4개 자료와 16개 과제의 원문 재산출·검토, v3와의 의미상 중복 검토, v4 출력 게이트의 실행 기록 연동 검증, `scripts/v4_preflight.py`의 ready 모드 통과, 코드·프롬프트·자료·채점 매니페스트의 해시 동결. 개발용 Kiro 2.23.0 실행과 프롬프트·증거 영수증, v4 실행기의 개발 자료 경로 점검은 통과했다. 동결 전에는 **v4 공식 실행을 시작하지 않는다**.

## 개발과 미공개 평가의 경계

현재 구현 검증은 `tests/test_v4_development.py`의 새로 만든 예시만 사용한다. 이 예시와 v3의 알려진 사례는 개발·회귀 자료이며 새 미공개 분모에서 제외한다. 미공개 과제를 본 뒤 규칙이나 프롬프트를 조정하면, 그 과제는 더 이상 미공개 평가로 주장하지 않고 새 평가 세트를 준비한다.
