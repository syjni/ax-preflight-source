# AX v5 사전등록 — 최종 응답 검증과 출력 전달

작성일: 2026-09-22. 실험 ID: `ax-exp-v5`. 이 문서는 **새 미공개 과제의 첫 Kiro 실행 전에** 고정할 설계다. `experiment/frozen/ax-exp-v5-manifest.json`이 존재하고 `scripts/v5_preflight.py`가 통과하기 전에는 공식 실행을 시작하지 않는다.

## 동기와 해석 범위

AX v4는 32개 유효 슬롯 중 1개만 확보하고 중단되었다. Kiro CLI 2.23.0 v2의 `runFinished.finalText`는 한 사용자 턴의 여러 `AssistantMessage` 텍스트를 이어 붙이고, 세션 턴의 `result.Ok.content`는 마지막 메시지만 담는다. v4 동결 실행기는 두 값을 전체 문자열로 비교했다. v4의 12개 시도·점수·동결 규칙은 보존하며, 무효 시도를 소급 유효화하거나 완료되지 않은 v4의 성공률을 계산하지 않는다.

v5는 **응답 범위에 맞는 독립적인 무결성 검사**를 개발용 자료에서 검증한 후 새 회사 자료와 새 질문으로 출력 계약의 실용 성능을 측정한다. 모델, 프롬프트, JSON 스키마, 전달 게이트와 내용 채점은 v4와 동일하게 유지해 주된 실행 변경을 스트림 검증에 한정한다. 단, 새 과제와 자료이므로 v4와 점수 차이를 인과 효과로 주장하지 않는다.

## 새로운 평가 세트와 실행 순서

- 새 `해솔제조` 자료 4개와 질문 16개: 비율 4, 임계값 4, 항목 집합 4, 정확 문자열 또는 근거 부족 보류 4. 보류 정답 2개를 포함한다. v3·v4의 ID 및 질문 문구 중복을 자동 거부하고 의미상 재사용도 동결 전 검토한다. v5 후보 16과제는 개발용 Kiro 호출에 사용하지 않는다.
- 후보 정답은 원문 자료에서 별도 검사기로 다시 산출한다. CSV 합계·정책 문장·항목 목록·승인팀과 보류 근거를 모두 확인한다. 소스 파일 4개 파싱·검색·읽기, CSV 표 조회, 런타임 정답 누출 검사, 자료·코드 해시 동결이 선행 조건이다.
- `claude-sonnet-5`, `kiro-cli-chat 2.23.0`, v2 엔진, 네 AX 읽기 도구를 사용한다. `v5-candidate` 한 증거 프로필에서 과제마다 새 프로세스·새 세션·단일 사용자 턴으로 2회씩, 총 **16 × 2 = 32개 유효 슬롯**을 계획한다. 매니페스트 순서로 1회차 전체를 수행한 뒤 2회차 전체를 수행한다.
- 모델에게는 `category`, `question`, `answer_kind`, 숫자 허용 단위만 전달한다. 정답·허용형·허용오차·보류 정답 여부·근거 경로는 전달하지 않는다. v4와 동일한 에이전트 프롬프트 텍스트를 v5 경로에서 해시로 동결한다.

## 응답과 실행 유효성의 분리

`scripts/session_prompt_validation.py`로 세션 JSON/JSONL의 정확한 제출 프롬프트 바이트, 단일 Prompt 및 사용자 턴, 최종 `result.Ok.content`를 확인한다. 새 `scripts/stream_response_validation.py`는 (1) 세션 JSONL의 모든 `AssistantMessage` 텍스트 연결, (2) 스트림의 `agent_message_chunk` 연결, (3) `runFinished.finalText`가 서로 같고, (4) 마지막 `AssistantMessage` 텍스트가 세션 턴 `result.Ok.content`와 같음을 요구한다. 여러 메시지가 있다는 이유만으로 실행을 무효화하지 않는다. 원문 답변은 **마지막 메시지 전체**로 고정하고 그 문자열을 출력 게이트와 채점기에 넘긴다.

새 세션·프로세스, v2 엔진 완료, 스트림 미절단, CLI 버전, 에이전트 설정·자료 영수증·소스 해시, MCP 호출 기록 및 프로세스 종료도 검사한다. 입력이나 런타임 증거의 실패는 `INVALID`로 별도 보존한다. 첫 INVALID에서 다음 슬롯으로 넘어가지 않고 원인을 조사한다. 환경의 일시적인 결함이 입증되면 해당 슬롯을 **최대 한 번** 별도 경로에서 재시도한다. 같은 결함이 되풀이되거나 스트림·세션 의미가 달라지면 실험을 중단하고 새 등록 여부를 검토한다. 답이 틀리거나 JSON 형식이 어긋난 응답은 `VALID` 실행으로 보존하며 재질문·재시도하지 않는다. 기존 기록은 덮어쓰지 않는다.

## 동결된 출력·채점 계약

v4의 `final_answer`, `unit`, `explanation`, `source_ids`, `abstain` 다섯 필드 스키마와 `scripts/v4_contract.py`, `scripts/v4_scoring.py`, `scripts/v4_evaluation.py`, `scripts/v4_prompt.py`를 그대로 사용하되 파일 해시를 v5 매니페스트에 다시 등록한다. 원문 전체가 단일 스키마 유효 JSON이면 원문 형식 성공이다. 결정론적 게이트는 원문을 보존하면서 유일한 스키마 유효 객체만 전달하고, 모호하거나 여러 객체가 있으면 거부한다. 게이트가 설명문을 제거해도 원문 형식 성공으로 세지 않는다.

숫자 답은 사전등록된 단위·배율·허용오차로 정규화한다. 항목 집합은 개념별 전체 문자열 일치와 사전등록 동의형만 허용하고, 누락·중복·추가 항목을 실패로 판정한다. 정확 문자열과 보류도 매니페스트의 허용형·보류 여부로 판정한다. 설명문으로 빠진 답을 보충하지 않는다.

**1차 지표:** 32개 유효 실행 중 고정 답 판정이 정답이고 게이트의 전달 JSON도 유효한 수. **보조 지표:** 마지막 모델 응답의 원문 엄격 JSON 준수, 게이트 후 전달율, 고정 내용 정답률, 게이트 거부율, 층별 성과, 과제별 두 반복의 일치율. 실행 수와 고유 과제 수를 함께 보고한다. 유효성 감사 전에 점수를 공식 합계에 넣지 않는다. v4의 미완료 기록을 비교군으로 쓰지 않는다.

## 동결 전 필수 검증과 금지 사항

개발용 한울상점 세션에서 여러 `AssistantMessage`가 생기는 상황을 실제로 재현하고 새 검사기가 세 가지 집계와 마지막 응답을 구분하는지 확인한다. 스트림 누락·오염, 세션 마지막 메시지 불일치, 절단 응답에 대한 거부 테스트를 통과시킨다. 그다음 **개발용 자료만** 사용하는 새 v5 실행기 전체 경로를 한 번 검증한다. 새 후보의 원문 정답 16/16, 소스 접근 4/4, 스캔과 런타임 누출, 중복 검사, 사전등록·코드·자료 해시를 모두 확인하고 동결한다.

공식 실행 중 v5 과제·자료·모델·프롬프트·출력 계약·채점·유효성 규칙을 수정하지 않는다. v5 후보 과제를 개발용 검증에 쓰거나 이미 본 v4 과제를 새 미공개 분모에 넣지 않는다. 동결 후 공식 Kiro 실행은 별도의 사용자 시작 지시가 있을 때 수행한다.
